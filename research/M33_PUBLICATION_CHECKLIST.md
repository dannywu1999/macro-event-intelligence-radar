## Gate before any user-approved publication

1. Verify the exact isolated research commit and file raw SHA256/Git blob identities from the final local publication manifest. Keep Production main and existing services unchanged.
2. Verify the exact-item review manifest locally against retained HTTPS policy/item receipts. Check the publisher's currently applicable terms. The stored hashes prove local byte integrity, not an independently signed legal entitlement.
3. Reproduce `python -m research.m33_public --study <existing-local-study> --public` offline. If policy/item hashes, title, byline, publication timestamp or review fingerprint differ, stop and obtain a fresh reviewed version; do not edit the old snapshot to make it pass.
4. Verify `M33_PUBLIC_EVENT_HANDOFF.json` carries identical publisher, author, licence/terms URL, changes and hash proof for each retained headline. The verified Fed proposition is publication/meeting coverage only, not a new FOMC rate decision.
5. Copy only the two JSON files to a separately reviewed static publishing bundle. Never copy the engineering directory, DATA/ITEMS/QUALIFICATION, mixed VOA records, review tools, tests, raw receipts, logs, secrets or local paths.
6. A website renderer must treat headline/author values as plain text, retain original links and licence references, and show original publication time separately from first-observed-in-M33. Do not publish original article bodies, excerpts, images or unreviewed translations.
7. The public snapshot is not a self-contained live adapter: it has no collector, database, secret, scheduler or writer. Do not copy the research checkout into a production Docker image.
8. Independently approve the exact destination and deployment action later. No Render/Gateway/Friends Preview deployment is included in this milestone. No new cloud service is required or authorized.
9. Periodic source access and future release-window tests need separate authorization and applicable publisher access terms. A CC content licence is not proof of unlimited server access or a 24/7 service guarantee.
10. If the scope is rejected, retain this research branch/evidence locally and publish nothing. No rollback or deletion of old evidence is needed because production was not changed.
